# EE871-E2 Code Audit Resolution Report (2026-08-31)

## Scope and source state

This is the updated report from a fresh audit of the completed audit work.
The originally requested `docs/CODE_AUDIT.md` is not present in the current
tree. The complete original finding set was recovered and reread from
`044ae2d^:docs/AUDIT_FINDINGS_2026-08-26.md`; the previous completion report
and the full `044ae2d^..044ae2d` implementation diff were also reviewed.

The fresh pass started from a clean, synchronized `main` at commit `044ae2d`.
Three parallel independent reviews covered core timing/reset behavior,
health/identity/read behavior, and examples/tooling. Their findings were then
checked against the actual source, tests, vendor-derived repository references,
and current diff before any correction was accepted.

## Original finding dispositions

### 1. Duplicated `begin()` / `busReset()` waveform — valid

The original consolidation into `_busResetRaw()` was retained. The fresh pass
found incomplete error cleanup around that implementation: STOP could return
while the master still commanded SDA low, reset did not prove that commanded
SCL-low phases were physically low, and cleanup STOP errors could be discarded.

The common START/STOP/reset path now:

- verifies commanded SCL-low and SDA-low/high levels;
- releases both master lines on every START/STOP failure;
- preserves cleanup failures when they are more precise than the interrupted
  transfer;
- handles reset STOP errors without collapsing SDA failures into an SCL label;
- allows the configured high-settle interval before sampling SDA for START.

Native cases cover SCL stuck low, SCL stuck high, SDA stuck low/high, SDA
release during reset clocks, STOP stretch timeout, line release after failure,
and health-neutral diagnostic reset.

### 2. Missing timing upper validation — partly valid; proposal corrected

The previous decision remains correct: independent 1,000 us high/low maxima
would not describe the waveform generated by this driver. The driver validates
the actual nominal period:

```text
10 us data setup + clockLowUs + clockHighUs <= 2,000 us
```

The fresh pass confirmed two remaining gaps and fixed both. `begin()` now also
enforces the specified 25,000 us per-bit and 35,000 us per-byte timeout maxima.
The byte deadline now reserves a complete high and low phase before allowing
clock-stretch polling to consume the remaining budget. A timeout therefore
occurs before a new bit starts or after preserving its protocol-minimum phases;
it can no longer truncate a low/high phase after changing a line.

The diagnostic timing commands were also corrected. Their slowest symmetric
candidate is 995/995 us because the transmitted period includes the 10 us data
setup, 50/75 us out-of-spec phases were removed, and displayed frequency now
uses the generated period.

### 3. Five-read burst spuriously reaches OFFLINE — invalid as reported

The original audit's transaction count remains incorrect. A NACK on the low
byte short-circuits each 16-bit read, so `readCo2Fast()` +
`readCo2Average()` + `readStatus()` records three failures, not five. The
default threshold remains five and the native regression still proves this.

The fresh pass did find a different OFFLINE bug: normal tracked operations
were still allowed to touch the bus, and one success could silently restore
READY. OFFLINE is now latched. Ordinary valid reads and writes return the last
precise tracked failure immediately, with no E2 traffic or counter change.
Raw `probe()` remains health-neutral, and only explicit `recover()` can restore
READY.

Recovery is now atomic from the health model's perspective. It performs a raw
bounded reset, complete raw identity check, and feature-cache refresh, then
records one success or one failure. Partial successful transfers cannot
temporarily restore READY, a failed recovery that began OFFLINE remains
OFFLINE, and a replacement device cannot inherit stale capability flags.

### 4. Torn 16-bit reads in E2-priority mode — invalid

No redundant low/high/low traffic was added. The EE871 low-byte read captures
the paired high byte, so the existing low-then-high MV3/MV4 sequence is the
correct and simplest protocol implementation.

Coverage was incomplete even though the implementation was correct. The fake
now supports configurable MV3/MV4 values and a targeted read NACK. Tests prove
normal values, 0/65,535 boundaries, output preservation when the high byte
fails, health accounting, and byte order. The adjacent custom-memory test now
also covers both CO2 calibration points, so every current adjacent pair named
by the earlier change is exercised with non-symmetric bytes.

### 5. `BUSY` / `IN_PROGRESS` are not returned — observation valid; removal rejected

No change was needed in the fresh pass. These public enum values remain
reserved for source/numeric compatibility. The synchronous implementation
does not return them, and the neutral `IN_PROGRESS` health branch remains a
small compatibility safeguard rather than a new asynchronous mechanism.

### 6. IDF scanner and `libtest` lagged Arduino hardening — valid

The previous `libtest` fix remains: both examples exercise the production
control-byte read path. Its help text now describes that limited scope instead
of claiming to test all library commands.

The fresh pass found that both scanners still duplicated raw signaling and did
not wait for clock stretching. Both now create a temporary driver per address,
run production `begin()` identity/capability/feature validation, and then run a
production status/PEC read. Five bounded attempts remain. A final NACK is
reported only as no complete compatible response, because it may occur after
successful identity traffic; an incompatible device or corrupt response is
reported with its precise status and is not mislabeled as “not a device.” A
non-NACK result is retained across later attempts so a final NACK cannot erase
that evidence.

The IDF and Arduino timing discovery paths likewise use temporary production
drivers, removing another place where diagnostic results could disagree with
the core transport.

### 7. Example divergences — valid

The earlier fixes for input overflow, sniffer warnings, ineffective IDF
polling, helper includes, and IDF component-name documentation remain in place.
The fresh pass additionally synchronized scanner behavior, timing candidates,
frequency calculation, incompatible-identity statuses, and `libtest` help
wording across Arduino and native ESP-IDF examples. The HIL plan expectations
were updated to match the truthful production-scanner output.

### 8. Tool/test cleanups — valid items fixed; optional logging churn rejected

The earlier fake/HIL/logging decisions remain. The fresh pass demonstrated two
false results in the static checks: removing comments before recognizing string
literals could hide real code after `"https://..."`, while scanning raw include
text could flag a commented-out `Arduino.h` include.

A small shared C/C++ lexical scanner now removes comments and literals in the
correct order while preserving layout. Contract checks use comment-free source,
scope dispatch requirements to the actual command processor, use
whitespace-tolerant call/count expressions, and verify that both scanners use
the production path. Four Python unit tests cover URLs/comment markers,
commented calls/includes, literals, and raw strings. CI now discovers all
`test_*.py` tool tests rather than only the HIL parser file.

`LOGD`, `LOGT`, and `LOGE` remain unchanged: removing selected zero-cost example
logging levels would still be unrelated churn.

## Additional requirements gaps found in the completed work

The fresh requirements review confirmed three correctness gaps not clearly
captured by the original eight headings:

1. `begin()` validated only the group identifier. It now validates group,
   subgroup, and advertised CO2 capability. A responding incompatible device
   returns `NOT_SUPPORTED`; absence and transport faults retain NACK, timeout,
   PEC, or bus-stuck status.
2. A feature-cache PEC/transfer failure previously allowed initialization with
   every optional capability silently disabled. Initialization now fails closed
   with the precise error instead of converting an uncertain cache into a valid
   device state.
3. OFFLINE and recovery did not match their documented managed-driver
   contract. The fail-fast latch and atomic recovery behavior described above
   now implement that contract directly without a scheduler, retry engine, or
   new public abstraction.

## Simplicity and scope review

The fixes stay inside the original core/examples/tests/tooling scope. No new
public API, heap allocation, background task, retry policy, platform dependency,
or generic bus framework was added. Identity validation and feature loading are
small private raw helpers, recovery is one tracked wrapper, and the OFFLINE
guard is centralized at the two tracked transport wrappers. Diagnostic scanners reuse the library
instead of growing a second stretch-aware protocol engine.

The original report's rejected proposals remain rejected: no unsupported
offline-threshold increase, no redundant measured-value consistency read, no
breaking enum removal, and no arbitrary logging cleanup.
